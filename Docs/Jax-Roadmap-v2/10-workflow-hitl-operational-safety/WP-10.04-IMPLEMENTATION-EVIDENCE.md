# WP-10.04 implementation evidence

Status: `IMPLEMENTED / INTERNALLY VERIFIED`

Workflow events are append-only audit records containing workflow identity,
sequence, prior/next state, action, actor, idempotency key, input fingerprint,
content identity, reason, UTC timestamp and transition version. Content
identity validation detects tampering; stream validation detects gaps and state
divergence; callers receive copies rather than mutable store internals.

State advancement and event append are atomic in the bounded store. Simulated
audit persistence failure leaves the workflow at its previous state. Postgres
migrations `000061_workflow_instances` and `000062_workflow_audit_events` add
additive persistence contracts with unique workflow sequence and idempotency
constraints.
