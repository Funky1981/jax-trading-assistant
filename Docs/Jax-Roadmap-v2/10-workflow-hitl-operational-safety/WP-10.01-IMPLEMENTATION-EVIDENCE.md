# WP-10.01 implementation evidence

Status: `IMPLEMENTED / INTERNALLY VERIFIED`

The bounded `internal/modules/workflow` state machine binds a workflow to the
exact Phase-09 recommendation, risk-decision, portfolio-snapshot, analytics,
policy and proposal identities. Risk `REJECT` cannot create a workflow. The
initial state is `RISK_ACCEPTED` or `RISK_AMENDED`; the only normal next step is
the explicit system transition to `AWAITING_HUMAN_CONFIRMATION`.

Transitions are typed, versioned, actor-checked, UTC-timestamped and
monotonic. Invalid jumps fail closed. State and its append-only transition
event are committed atomically by the store; audit persistence failure leaves
state unchanged. Idempotency keys return the original result only when the
command content matches, otherwise they fail with a conflict.

Verification:

- `go test ./internal/modules/workflow -count=1` — PASS.
- Covered: exact risk binding, risk rejection, illegal state jumps, UTC
  validation, atomic audit failure, idempotent retry and audit replay.

portfolio mutation. Human confirmation and inert paper intent remain later
explicit transitions in this phase.
