## Required implementation characteristics
- Keep the package bounded and reversible where practical.
- Prefer explicit typed/versioned contracts between runtimes.
- Do not introduce a new runtime/language unless the capability boundary justifies its operational cost.
- Preserve deterministic validation around AI outputs.
- Add observability appropriate to the failure modes introduced.
- Exact result reuse must use a complete, versioned validity key covering task, prompt/output contract, model compatibility, evidence fingerprint/vintage, relevant policies/tools and material runtime options.
- Reused results remain explicitly labelled and retain original provenance; cache/reuse never bypasses current freshness, portfolio/risk or execution gates.
- Semantic result reuse remains disabled unless a later separate architecture review proves acceptable false-hit/freshness behaviour.

- Invalidation tests prove no reuse across material prompt/model/evidence/policy/vintage changes.
- Operator-visible errors/failures do not masquerade as success.
