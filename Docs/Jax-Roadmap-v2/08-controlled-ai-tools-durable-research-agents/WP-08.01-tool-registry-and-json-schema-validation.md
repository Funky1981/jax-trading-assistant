## Internal implementation evidence

- Extended the existing `internal/modules/harness` boundary with
  `jax.controlled_tool_registry/v1`, typed controlled-tool specifications and a
  deterministic registry.
- Tool specifications require version, bounded timeout, output contract,
  permission tier, cost class, provider, provenance behavior, read-only status
  and a handler. The registry rejects duplicates, unsafe definitions and
  unknown tool requests.
- Added bounded JSON argument validation for required fields, unknown fields,
  enums, identifiers, UTC timestamps, numeric bounds, arrays, property counts,
  byte size and trailing JSON. No arbitrary tool names or arbitrary execution
  surfaces are accepted.
- Verification: `go test ./internal/modules/harness -count=1`.
