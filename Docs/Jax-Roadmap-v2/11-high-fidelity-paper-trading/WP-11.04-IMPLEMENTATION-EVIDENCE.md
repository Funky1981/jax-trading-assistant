# WP-11.04 implementation evidence

Status: `IMPLEMENTED / INTERNALLY VERIFIED`

Paper orders now have explicit `NEW`, `ACTIVE`, `PARTIALLY_FILLED`, `FILLED`
and `CANCELLED` states. A tick's available quantity is consumed across
orders, so filled plus remaining quantity cannot exceed the original order.
Cancellation is explicit and idempotent; a cancelled order cannot fill.
Orders activate only once latency has elapsed. CLOSED sessions keep orders
pending without fills, while UNKNOWN sessions fail closed. Ticks must be UTC,
strictly ordered, non-stale and explicitly sourced.

Verification:

- `go test ./internal/modules/papertrading -count=1` — PASS.
- Covered closed/unknown sessions, bounded liquidity partial fills, exact
  quantity invariants, cancellation, no overfill and post-cancel no-fill.

No market calendar was invented; the contract requires an explicit session
from the market-data boundary.
