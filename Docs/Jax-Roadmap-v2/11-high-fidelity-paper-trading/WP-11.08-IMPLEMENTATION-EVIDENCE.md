# WP-11.08 implementation evidence

Status: `IMPLEMENTED / INTERNALLY VERIFIED`

The versioned `SoakProtocol` defines a six-month target duration, minimum
sample, failure thresholds and safety completion criteria. `SoakRun` records
recommendations, eligible intents, orders, fills, partial fills, crashes,
breakers, reconciliation failures and duplicate fills. Negative balance, audit
gap, live-path activation, duplicate-fill threshold and reconciliation failure
threshold fail the run. The protocol distinguishes
`SOAK_INFRASTRUCTURE_DEMONSTRATED`, `ACCELERATED_SYNTHETIC_SOAK` and
`REAL_TIME_FORWARD_SOAK`; accelerated tests never report actual forward
duration.

The Phase-11 exit harness in `internal/modules/papertrading/phase11_exit_test.go`
proves the complete recommendation/risk/HITL/paper-intent/paper-order/fill/
ledger/reconciliation/attribution path, restart idempotency and breaker
blocking. It uses frozen synthetic fixtures and is not a claim of six months
of elapsed paper trading.

Persistence migrations `000064` through `000067` add isolated paper orders,
fills, ledger events/accounts and soak runs/events. Paper fills, ledger events
and soak events are append-only; all active migration versions remain unique.
