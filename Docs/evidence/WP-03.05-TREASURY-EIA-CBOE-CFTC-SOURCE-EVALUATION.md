# JAX HANDOVER — WP-03.05 TREASURY / EIA / CBOE / CFTC SOURCE EVALUATION

Status: **IMPLEMENTED — awaiting independent technical-lead review**

This package evaluates all four first-party source families and implements the
smallest bounded set that passed source-contract and live-access checks:
Treasury Daily Treasury Par Yield Curve Rates and Cboe VIX daily historical
values. No trading, recommendation, signal, cross-source, or execution logic
was added.

## Implemented integrations

### Treasury

`libs/treasury` implements `AcquireYear`, using the official year-bounded XML
feed for `daily_treasury_yield_curve`. The provider identity is
`pvd_treasury` in namespace `treasury.interest_rates`; the logical source is
`src_treasury_daily_par_yield_curve`. Authentication is `NONE`. The provider
capability is the existing `macro.observation` capability and the output is
`jax.macroevidence/macro_observation/v1`.

The raw representation is provider-bound `treasury.daily_interest_rate_xml/v1`
with `text/xml`. Each year request is one bounded source artifact. XML rows are
validated as strictly ascending dates inside the requested year. The adapter
normalizes the 14 nominal tenors from the official fields (`BC_1MONTH` through
`BC_30YEAR`) into provider-neutral `MacroSeries` and `MacroObservation` values.
The provider field identity is retained in `ProviderSeriesID`, for example
`daily_treasury_par_yield_curve:BC_10YEAR`; no FRED identity is inferred.

The source lexical value is retained in `MacroValue.SourceValue` and the
finite `Number` is convenience data only. Empty/null/N/A source cells remain
missing with no zero substitution. Observation dates remain date-only. The
feed-level `updated` timestamp is retained as series `LastUpdated`, but is not
used as an observation publication or availability instant. The result reports
`COMPLETE` only for the requested year artifact after validation.

### Cboe

`libs/cboe` implements `AcquireHistory` against the official linked VIX CSV.
The provider identity is `pvd_cboe` in namespace `cboe.index_data`; the logical
source is `src_cboe_vix_daily_history`. Authentication is `NONE`. It uses the
existing `macro.observation` capability and
`jax.macroevidence/macro_observation/v1` output.

The raw representation is provider-bound `cboe.vix_history_csv/v1` with
`text/csv`. The adapter requires the documented five-column header, parses the
daily `CLOSE` field as VIX index evidence, rejects malformed rows, rejects
duplicate or non-ascending dates, and preserves each close lexical value.
`DATE` becomes `ObservationDate`; no timestamp is fabricated from a market
close or HTTP metadata. The result is `COMPLETE` only for the returned CSV
artifact. It is not described as a universal or eternally complete VIX archive.

## Raw evidence and provider boundaries

Both adapters execute through the shared Phase-02 `OperationalExecutor`, then
call the shared `provider.PersistRawPayload` with the exact entity-body bytes.
They retrieve the bytes through `provider.RetrieveRawPayload` and parse only
the verified read-back. They do not create a filesystem cache, provider table,
parallel evidence store, or database migration. Raw payload revisions are
SHA-256 identities, and normalized provenance points back to the immutable raw
payload evidence reference.

The HTTP DTO/parser representations are private to each adapter package. The
returned records contain only `macroevidence.MacroSeries` and
`macroevidence.MacroObservation`; no provider DTO, CSV reader type, XML type,
HTTP client type, or third-party library type crosses the provider-neutral
boundary.

## Temporal and point-in-time safety

For Treasury and Cboe, `ObservationDate` is distinct from any source feed
metadata and from `AcquiredAt`. Treasury’s feed `updated` value is not a claim
that every row became publicly available at that instant. Cboe’s downloaded
historical file does not prove when any historical row first became knowable to
Jax. No midnight UTC, market-close, or publication timestamp was inferred.

For the deferred CFTC candidate, report-as-of date, report release date, actual
public-availability instant, and acquisition time remain conceptually separate;
the adapter was not implemented. For EIA, source period, revision, release or
availability metadata, and acquisition time would likewise require separate
source evidence.

Historical artifacts acquired now establish the source contents of the
artifact, not historical knowability. Backtests must use an explicitly
reviewed publication/availability policy or abstain from claiming point-in-time
knowledge.

## Verification and limitations

Deterministic tests cover provider identity and capability declaration, exact
raw bytes and read-back, provenance linkage, provider-neutral output, lexical
numeric values, missing values, date-only semantics, malformed XML/CSV,
duplicate dates, strict ordering, bounded completeness, and credential-free
operation. Guarded live smoke tests cover the real Treasury XML and Cboe CSV.

The package intentionally does not implement CFTC positioning, EIA series
acquisition, release timestamps, source-revision reconciliation, qualification
decision persistence, freshness TTL policy, signals, analytics, or
cross-source corroboration. Cboe redistribution rights are conservative and
must be reviewed before any external redistribution. Treasury government-data
retention is also not treated as blanket redistribution authorization.

No credential appears in raw payloads, provenance, normalized evidence, logs,
errors, fixtures, or committed files. No credential was requested from the
user or fabricated.

Trading/execution safety was not changed. Hosted model inference was not used.
WP-03.06 was not started.

Recommended technical-lead decision: **GO**, subject to independent review of
the bounded Treasury/Cboe source qualification, conservative Cboe rights
posture, and the explicit EIA/CFTC deferrals. This is only a recommendation;
