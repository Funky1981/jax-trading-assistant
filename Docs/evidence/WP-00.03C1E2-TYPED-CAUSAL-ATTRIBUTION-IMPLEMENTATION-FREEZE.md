# WP-00.03C1E2 — Typed causal-attribution implementation freeze

## Decision and scope

C1E2 implements the accepted C1E1 architecture as an isolated v5 path. It
does not change the v4 prompt, v4 output contract, C1D v1 behavior, resolver,
datasets, ticker-token detector, trading behavior, or provider authorization.
No model inference or provider contact occurred.

The implemented flow is:

`validated v5 raw output -> typed C1E policy -> effective semantic mapping -> event-asset-resolution-v1`

Go reads only the typed attribution arrays when making the C1E selection. It
does not reconstruct causality from event prose, entities, `reason`,
`missing_evidence`, or `market_relevance`.

## Exact v5 contract

The ten v4 field names and basic types are retained under the new v5 identity.
Two required fields are added:

- `issuer_attributions`: array, maximum 10, with closed items containing only:
  - `issuer`: trimmed non-empty string, maximum 200 characters;
  - `causal_role`: `PRINCIPAL`, `EQUAL_PRINCIPAL`,
    `SECONDARY_AFFECTED`, `CONTEXT_ONLY`, or `POSSIBLE_PRINCIPAL`.
- `principal_proxy_candidates`: array of the active resolver-derived bounded
  exposure keys, excluding `NONE`; the schema maximum equals the active
  exposure count. No second proxy vocabulary exists.

The strict OpenAI adapter sends the canonical `ProviderRequest.Schema` as
`text.format.schema`, with type `json_schema`, the v5 schema name, and
`strict=true`. The request carries the contract identity and canonical schema
hash; a modified schema or hash fails before HTTP. Mocked tests also verify
`reasoning.effort=none`, `store=false`, the configured output-token ceiling,
the default service tier, no tools/web/retrieval, and no expected labels.

## Cross-field invariants

The application validator enforces:

1. Attribution and proxy arrays are present, non-null, bounded, and contain
   only schema-defined items.
2. Issuer identities are unique after `CanonicalizeIssuerName`; proxy
   candidates are unique after trim/case normalization.
3. At most one `PRINCIPAL` is allowed.
4. `EQUAL_PRINCIPAL` occurs zero times or at least twice.
5. `PRINCIPAL`, `EQUAL_PRINCIPAL`, and `POSSIBLE_PRINCIPAL` cannot coexist.
6. Any principal/equal/possible role requires no proxy candidates.
7. `SECONDARY_AFFECTED` and `CONTEXT_ONLY` do not create DIRECT eligibility.
8. DIRECT requires exactly one `PRINCIPAL`, no other principal class, no proxy
   candidates, `proxy_exposure=NONE`, and a `direct_issuer` exactly equal to
   the principal identity after trimming.
9. PROXY requires no principal/equal/possible roles, exactly one proxy
   candidate, empty `direct_issuer`, and an exactly matching
   `proxy_exposure`.
10. UNRESOLVED requires empty `direct_issuer`, `proxy_exposure=NONE`, LOW
    mapping confidence, and a typed equal/possible/no-candidate/multi-proxy
    state.
11. A unique principal must project DIRECT even when the resolver does not
    recognize it; a unique proxy must project PROXY.
12. Existing receipt-time and confidence rules remain. Relevance, horizon,
    direction, and catalyst fields receive no new causal coupling.
13. Impossible projections fail validation. They are never coerced, and the
    resolver is not invoked for invalid output.

## Deterministic C1E policy

`ai-shadow-causal-attribution-c1e-v1` has three outcomes:

- unique `PRINCIPAL`: accept DIRECT and pass that exact issuer to
  `ResolveIssuer`;
- no direct principal class and exactly one proxy candidate: accept PROXY and
  pass that candidate to `ResolveProxyExposure`;
- equal principals, possible principals, no candidate, or multiple proxy
  candidates: abstain UNRESOLVED.

The policy cannot choose among equal issuers or proxies, promote secondary or
context issuers, substitute a proxy for an issuer, or invent a mapping.
Unknown resolver coverage remains a resolver result after a semantic DIRECT;
it does not rewrite semantic classification.

Typed reason codes make policy behavior auditable, including
`POSSIBLE_PRINCIPAL_ISSUER`. The v5 report family has separate counters for
possible-principal occurrences, abstentions, correct ambiguity, and associated
false negatives. No frequency threshold is imposed.

## Attribution completeness and prompt

The v5 prompt separates causality from relevance, presence from causality,
one principal among many from equal causality, unknown issuers from resolver
coverage, and direct ambiguity from legitimate proxy selection. It explicitly
requires every issuer identity needed to represent the event's causal
structure, including non-selected secondary/context issuers, and forbids
omitting an equal principal to manufacture a single-principal event.

Completeness is semantic and is not enforced with a Go entity/NLP extractor.
The typed raw output is retained so C1E3 can score completeness against a
separately frozen typed label sidecar.

## Evidence-layer separation and compatibility

V5 persistence and attempt audit retain independently:

1. raw v5 model output;
2. copied typed issuer/proxy attribution;
3. C1E policy decision and typed reason code;
4. effective semantic mapping;
5. unchanged deterministic resolver result.

The v5 decoder is a separate branch. V1, v2, v3, and v4 decoders remain
unchanged and readable. V4 continues to require the v4 prompt and historical
C1D v1 policy. V5 requires the v5 prompt and C1E policy. Mixed and unknown
prompt/contract/policy combinations fail closed.

C1D v1 remains present and reproducible but cannot be selected for v5. Its
source file was not modified. Ticker-token detection was not modified and its
historical lexical metric remains separately versioned.

is named separately.

## Offline regression evidence

Synthetic policy fixtures cover unique principal, principal among context,
unknown principal, equal principals, possible principal, secondary-only,
unique proxy, multiple proxies, LOW-relevance DIRECT, and changed audit prose.
Impossible fixtures cover missing typed fields, duplicate normalized issuers,
role cardinality and coexistence errors, every forbidden PROXY/principal
combination, no/multiple/mismatched proxy candidates, principal mismatch, and
invalid UNRESOLVED projections. One rejected first response followed by one
valid corrective response proves the existing retry remains bounded to one.

These are offline policy regressions, not actual Luna v5 results. No model-level
v5 accuracy is claimed.
