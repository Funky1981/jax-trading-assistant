# WP-01.02 - Canonical Jax Domain Contracts

## Control and scope

- Work package: `WP-01.02 - Define canonical Instrument/Issuer/Event/Evidence/Observation/ResearchRun/QuantResult/Recommendation contracts`
- Starting commit: `4357c5880bfb85a84dd1fe98c25ca5c6c5458389`
- Branch: `capability-reset`
- Accepted input evidence: `Docs/evidence/WP-01.01-JAX-DOMAIN-CONTRACT-INVENTORY.md`
- Canonical Go owner: `jax-trading-assistant/libs/contracts/canonical`
- Runtime effect: none. This package defines the destination contracts; it does not migrate a producer, consumer, API, persistence path, or frontend.
- Database effect: none. No migration or persisted state is required.
- Stop boundary: WP-01.03 provenance and WP-01.04 replay/audit work are explicitly deferred.

## Ownership and dependency direction

`libs/contracts` is already Jax's shared cross-runtime contract module. A dedicated `canonical` package inside that module is the smallest clean owner because both Go runtimes can import it without reversing the ADR-0012 dependency direction.

The existing `libs/contracts/domain` package was not selected as canonical ownership. It is an active compatibility surface for Signal, Order, Position, Portfolio, and OrchestrationRun service DTOs. Those types include HTTP/execution-era semantics and untyped maps and are classified `LEGACY` or compatibility-oriented by WP-01.01. Mixing the Phase 01 vocabulary into that package would make the ownership boundary ambiguous.

The resulting direction is:

```text
provider / SQL / HTTP / frontend / AI / broker representations
                             |
                     explicit adapters
                             |
        libs/contracts/canonical (sole canonical owner)
                             |
               downstream domain/application use
```

No owner module loses ownership of feature state. Artifact trust, datasets, instrument eligibility policy, asset resolution, genuine event decisions, candidates, approvals, paper tickets, risk policy, and audit storage remain in their current packages.

## Common contract mechanics

| Mechanic | Definition |
| --- | --- |
| Contract version | Every top-level record has `contract_version`. V1 identities are `jax.instrument/v1`, `jax.issuer/v1`, `jax.event/v1`, `jax.evidence/v1`, `jax.observation/v1`, `jax.research_run/v1`, `jax.quant_result/v1`, and `jax.recommendation/v1`. |
| Canonical identity | Distinct Go ID types use `ins_`, `iss_`, `evt_`, `evd_`, `obs_`, `run_`, `qnt_`, and `rec_` prefixes. The suffix is opaque and may be assigned or deterministically derived by an adapter. The package does not force UUID generation. |
| External identity | `ExternalID{namespace,value}` preserves provider, venue, registry, or persistence identity separately from Jax identity. Namespace is a lower-case code. |
| Cross-contract reference | `ContractRef{kind,id,contract_version}` is a typed schema-aware identity link among the eight contracts. It is not the immutable evidence/provenance reference deferred to WP-01.03. |
| Source placeholder | `SourceReference{id,kind,external_id/uri}` supplies the minimum source attribution needed for sound Evidence and Observation records. It intentionally has no content hash or lineage graph. |
| Component placeholder | `ComponentRef{kind,name,version}` identifies the method, algorithm, model, tool, or policy used by ResearchRun/QuantResult without importing provider or orchestration DTOs. |
| Record semantics | Contracts are Go values with no mutator methods. A changed historical meaning is represented by a new record/version at its owning boundary; append-only persistence policy remains WP-01.04 work. |

## Canonical contract definitions

### Issuer

Issuer is the legal/economic entity responsible for securities or business activity. It is not a ticker or tradeable security.

| Field | Semantics |
| --- | --- |
| `contract_version`, `id` | Schema identity plus stable Jax issuer identity. |
| `type` | `corporate`, `sovereign`, `government_agency`, `supranational`, `fund`, `fund_sponsor`, or `other`. |
| `name`, `jurisdiction` | Required display/legal name and optional upper-case ISO alpha-2 jurisdiction. |
| `external_ids` | Optional LEI/provider/registry identities; never canonical IDs. |
| `parent_issuer_id` | Optional typed parent relationship; self-parenting is invalid. |
| `effective` | Optional economic applicability interval. |
| `created_at` | UTC time the canonical record was created. |

### Instrument

Instrument is the tradeable or measurable financial instrument. Apple Inc. and its common stock are therefore separate Issuer and Instrument records.

| Field | Semantics |
| --- | --- |
| `contract_version`, `id` | Schema identity plus stable Jax instrument identity. |
| `type` | `equity`, `etf`, `etn`, `fund`, `index`, `rate`, `commodity`, `fx_pair`, `digital_asset`, `derivative`, `economic_series`, or `proxy`. |
| `name` | Required instrument name. |
| `currency`, `measurement_unit` | Optional currency and unit, allowing both tradeable securities and measurable rate/index/economic-series records. |
| `external_ids` | At least one venue/registry/provider identity such as ticker+venue, ISIN, or series code. A symbol is not the canonical ID. |
| `issuers` | Zero or more typed issuer relationships with `issuer`, `sponsor`, `administrator`, `sovereign`, or `reference_entity` role. Zero is valid for commodities, indexes, rates, and similar subjects. |
| `relationships` | Optional `underlying`, `tracks`, or `proxy_for` links to other Instruments. These describe identity/economic relationships, not Phase 00 eligibility or resolution policy. |
| `effective`, `created_at` | Optional economic applicability interval and required UTC record creation time. |

### Event

Event is a domain occurrence or asserted occurrence. An article reporting an occurrence is Evidence, not automatically the Event.

| Field | Semantics |
| --- | --- |
| `contract_version`, `id` | Schema identity plus stable Jax event identity. |
| `type` | `corporate_action`, `earnings`, `macro_release`, `regulatory`, `geopolitical`, `market_structure`, `news`, or `other`. |
| `assertion` | `asserted`, `confirmed`, `disputed`, or `retracted`; the contract does not silently convert an assertion into a fact. |
| `title`, `summary` | Required concise title and optional bounded description. |
| `subjects` | Optional Instrument/Issuer references. A global event may have no resolved subject. |
| `external_ids`, `related_event_ids` | Provider identities and explicit related Event IDs, separate from canonical identity. |
| `occurred_at`, `effective_at` | At least one is required. They remain separate because announcement, occurrence, release, and economic effectiveness can differ. |
| `created_at` | UTC time the canonical Event record was created. It is not treated as occurrence time. |

### Evidence

Evidence is one source-backed item that supports, contradicts, or describes a target. It does not become an Observation merely because it contains numbers.

| Field | Semantics |
| --- | --- |
| `contract_version`, `id` | Schema identity plus stable Jax evidence identity. |
| `type` | `article`, `filing`, `official_release`, `transcript`, `document`, `dataset`, `research_output`, or `model_output`. Provider/model response shapes remain adapters before this point. |
| `title`, `summary` | Required title and optional bounded description of the item. |
| `source` | Required typed source placeholder with a stable `src_` identity and external ID and/or absolute URI. |
| `links` | One or more typed targets plus `supports`, `contradicts`, or `describes`. Evidence cannot target another Evidence record in V1, avoiding a premature provenance graph. |
| `published_at` | Optional source publication time. |
| `collected_at` | Required time Jax/provider collection completed; it cannot precede a known publication time. |
| `created_at` | Required canonical record creation time; it cannot precede collection. |

### Observation

Observation is a measured or recorded value/state at a time. Prices, yields, volumes, macro values, fundamentals, measurements, and states are represented without making them Events.

| Field | Semantics |
| --- | --- |
| `contract_version`, `id` | Schema identity plus stable Jax observation identity. |
| `type` | `price`, `yield`, `volume`, `macro_value`, `fundamental`, `measurement`, or `state`. |
| `subject` | Exactly one Instrument, Issuer, or Event reference. Economic series can be represented as Instruments. |
| `metric` | Required lower-case semantic metric code. |
| `value` | Closed union of number, text, or boolean. Exactly one typed value is present; numeric values require a unit. |
| `source` | Required source placeholder. |
| `evidence_ids` | Optional typed Evidence identities that substantiate the measurement. These are identity links, not WP-01.03 immutable EvidenceRefs. |
| `observed_at` | Time the value/state applies to. |
| `published_at` | Optional time the measurement was published, separate from observation time. |
| `collected_at`, `created_at` | Collection and canonical creation times, ordered after the applicable earlier roles. |

### ResearchRun

ResearchRun is one bounded research computation/process. It links identified inputs to a versioned method/model/tool and identified outputs without defining an agent framework or redesigning orchestration.

| Field | Semantics |
| --- | --- |
| `contract_version`, `id` | Schema identity plus stable Jax run identity. |
| `type` | `analysis`, `backtest`, `evaluation`, `screening`, `synthesis`, or `other`. |
| `status` | `pending`, `running`, `succeeded`, `failed`, or `cancelled`, with status-specific time/output/failure rules. |
| `method` | Required method/algorithm/model/tool/policy name and version. |
| `input_refs` | At least one schema-aware canonical input identity. Dataset snapshots enter canonically as Evidence rather than machine-local paths. |
| `output_refs` | Typed output identities. Succeeded runs require at least one; partial outputs may remain visible on failed runs. |
| `parent_run_id` | Optional bounded parent relationship; self-reference is invalid. |
| `failure` | Typed code/message required only for failed runs. It is not a provider stack trace. |
| `created_at`, `started_at`, `completed_at` | Separate lifecycle clock roles with deterministic status-specific ordering. |

### QuantResult

QuantResult is a deterministic/statistical numeric result from identified inputs. It is not a JSON metrics map and does not implement any Phase 05 algorithm.

| Field | Semantics |
| --- | --- |
| `contract_version`, `id` | Schema identity plus stable Jax result identity. |
| `type` | `scalar`, `series`, `distribution`, `ranking`, or `statistics`. |
| `research_run_id` | Required producing ResearchRun identity. |
| `method` | Required versioned calculation/algorithm reference. |
| `input_refs` | At least one identified canonical input; self-reference is invalid. |
| `values` | One or more named finite numeric `QuantValue` records with unit, optional UTC observed time, optional ranking ordinal, and ordered typed dimensions. Series points require observation time; rankings require positive rank. |
| `calculated_at` | UTC time the result was calculated. |

Metric names and typed dimensions provide extensibility without hard-coding every future indicator and without using `map[string]any`. Slice order is part of the canonical representation.

### Recommendation

Recommendation is Jax research/decision-support output. It is not an approval, execution instruction, order intent, order, fill, or permission to bypass deterministic risk/HITL/execution gates.

| Field | Semantics |
| --- | --- |
| `contract_version`, `id` | Schema identity plus stable Jax recommendation identity. |
| `disposition` | Deliberately preserves `NO_TRADE`, `WATCH`, and `CANDIDATE`. `CANDIDATE` is a classification and is not the active candidates aggregate or an approval. |
| `research_run_id` | Required producing ResearchRun. |
| `subjects` | At least one Instrument, Issuer, or Event subject. |
| `basis` | At least one Event, Evidence, Observation, ResearchRun, or QuantResult reference. |
| `reasons` | One or more unique typed reason codes with human-readable summaries. |
| `confidence` | Optional finite value in `[0,1]`; absence is distinct from zero. |
| `authority` | V1 accepts only `RESEARCH_DECISION_SUPPORT`. |
| `execution_authority` | V1 accepts only `NONE`. The contract contains no side, quantity, order, approval, broker, or fill field. |
| `created_at`, `valid_until` | Creation time and optional strictly later validity horizon. Neither authorizes action. |

## Identity strategy

Jax identity, external identity, deterministic identity, and relationships remain distinct:

1. Canonical IDs are typed and prefixed, but the package does not generate them. An adapter can use a durable assigned ID or deterministic derivation while retaining the same semantic type.
2. Provider/venue/registry values remain `ExternalID`s and cannot satisfy a canonical ID field directly.
3. `ContractRef` carries kind, canonical ID, and schema version so a malformed or cross-kind reference fails validation.
4. Parent/related links are explicit: issuer parent, instrument economic relationship, related event, and parent research run.
5. Content hashes, input fingerprints, immutable EvidenceRefs, and complete provenance identity are deliberately deferred to WP-01.03.

Using kind prefixes rather than UUID-only fields preserves compatibility with current UUIDs, deterministic prefixed IDs, content-derived identities, and provider keys discovered by WP-01.01. Adapters may embed a UUID as the suffix but cannot use an untyped bare UUID as canonical identity.

## Timestamp and clock strategy

All canonical `time.Time` values must be non-zero where required and have UTC offset `+00:00`. Standard Go JSON encoding uses RFC 3339/RFC 3339 Nano. A non-UTC wall-clock representation is rejected instead of silently normalized because the boundary must make its clock conversion explicit.

| Contract | Distinct roles |
| --- | --- |
| Issuer / Instrument | economic `effective.from/to`; canonical `created_at` |
| Event | domain `occurred_at`; economic `effective_at`; canonical `created_at` |
| Evidence | source `published_at`; acquisition `collected_at`; canonical `created_at` |
| Observation | applicability `observed_at`; release `published_at`; acquisition `collected_at`; canonical `created_at` |
| ResearchRun | lifecycle `created_at`, `started_at`, `completed_at` |
| QuantResult | computation `calculated_at` |
| Recommendation | decision-support `created_at`; applicability `valid_until` |

Ordering is enforced only where semantics require it. Event occurrence/effectiveness are not ordered against creation because scheduled future events and historical backfills are legitimate. Evidence, Observation, ResearchRun, and Recommendation lifecycle relationships are ordered because the later role cannot semantically precede the earlier role.

## Version and JSON compatibility strategy

- Each family has an exact V1 schema identity. Empty, unknown, or future versions fail closed.
- A reference carries the referenced family version and must match that family's supported version.
- `EncodeJSON` validates before emission. `DecodeJSON` requires a non-nil typed pointer, rejects unknown fields and trailing JSON values, and validates after decoding.
- Canonical structs contain no maps. Struct field order and producer-supplied slice order define stable JSON bytes for the same value. The representative Recommendation fixture is `libs/contracts/canonical/testdata/recommendation_v1.json`.
- Because V1 decode is strict, adding or changing a field requires a new explicit contract version and a boundary translation/compatibility decision. Existing V1 remains readable under its own schema.
- Contract schema version is not record revision, component build identity, evidence content identity, or replay identity. WP-01.03 owns the missing provenance/version identity model.

Direct `encoding/json.Unmarshal` cannot prove acceptance; a boundary must call `DecodeJSON` or call `Validate` explicitly after its own decoder.

## Deterministic validation strategy

Validation returns a typed `ValidationError` with contract, field, and failed rule. Checks execute in stable field order and return the first error.

| Contract | Material negative states rejected |
| --- | --- |
| All | unsupported version; empty/malformed canonical ID; invalid typed references; non-UTC required times |
| Issuer | missing type/name; malformed jurisdiction; self-parent; reversed effective period |
| Instrument | missing type/name/external identity; malformed currency; duplicate issuer/economic links; self-relationship; reversed effective period |
| Event | missing type/assertion/title; invalid subjects; self/duplicate related events; neither occurrence nor effective time |
| Evidence | missing source or target; evidence-to-evidence target; unknown relationship; collection before publication; creation before collection |
| Observation | invalid subject; missing metric/source; zero or multiple union values; non-finite number; missing numeric unit; impossible publication/collection/creation order |
| ResearchRun | missing input/method/status/type; self-reference; impossible status/time/output/failure combination |
| QuantResult | missing result type/run/method/input/value; self-input; NaN/infinity; invalid series/ranking semantics; duplicate dimensions/value identity |
| Recommendation | unknown disposition; missing producer/subject/basis/reason; invalid confidence/horizon; any authority other than research decision support; any execution authority other than `NONE` |

## A-01 through A-12 disposition

| Decision | WP-01.02 disposition |
| --- | --- |
| A-01 Canonical ownership | Resolved: `libs/contracts/canonical` is the sole canonical package. Existing owner modules keep feature state and boundary shapes. |
| A-02 Identity | Resolved for V1: typed prefixed Jax IDs, separate namespaced external IDs, schema-aware references, and explicit parent/related links. UUID is permitted as an opaque suffix, not forced. Provenance/content identity remains A-04/WP-01.03. |
| A-03 Time semantics | Resolved for these contracts: separate occurred/effective, observed, published, collected, created, calculated, run lifecycle, and validity roles; UTC required. No generic `Timestamp` exists. |
| A-04 Provenance/version minimum | Partially resolved at the authorized boundary: every contract/ref has schema version; evidence/observation have typed source placeholders; run/result have component version. Content/input/policy/model lineage and immutable evidence identity are explicitly WP-01.03. |
| A-05 Event boundary | Resolved: canonical Event is an occurrence/assertion record. World Monitor/provider, normalized SQL, joined evaluation, and feature events remain adapters/projections. |
| A-06 Evidence/Observation boundary | Resolved: distinct source-backed Evidence and time-applicable Observation contracts with typed links. No generic polymorphic evidence bundle was introduced. |
| A-07 Instrument/Issuer | Resolved: broader identity records are defined separately from eligibility and resolver policies. Multiple issuer relationships and issuer-less instruments are supported. Phase 00 resolver/catalog remain unchanged. |
| A-08 ResearchRun/QuantResult | Resolved: canonical domain records map to existing engine/API/table shapes; no duplicate subsystem or persistence was added. Quant extensibility is typed values/dimensions, not JSON maps. |
| A-09 Recommendation authority | Resolved: `NO_TRADE/WATCH/CANDIDATE` retained as disposition; authority is fixed to research decision support and execution authority to `NONE`. Candidate/approval/execution types remain distinct. |
| A-10 Audit/history | Carried forward intentionally: V1 uses immutable value/record semantics and is replay-capable, but append-only history/current projections/audit event strategy is WP-01.04. |
| A-11 Compatibility | Resolved for WP-01.02: retain all existing active/legacy/feature-local types; classify and adapt later. No deletion, deprecation, or repository-wide migration. |
| A-12 API schema | Resolved for V1: typed Go + strict deterministic JSON at the canonical boundary. Existing Go/TypeScript APIs remain projections. No OpenAPI/JSON Schema/code generation is introduced without a demonstrated consumer. |

## Compatibility and intentionally unmigrated boundaries

No production adapter is necessary to satisfy WP-01.02 because no controlling runtime consumer is required. Compilation, validation tests, strict JSON round trips, and the fixture prove the contracts are usable without forcing speculative runtime coupling.

The following remain intentionally unchanged:

- World Monitor ingestion, persistence, subject evaluation, and decision history;
- Phase 00 causal prompt/schema/validator/policy/comparator/resolver and benchmark evidence;
- instrument eligibility catalog and asset-resolution rules;
- candidates, approvals, paper tickets, paper outcomes, and risk review;
- research/backtest engines, orchestration, AI/model/provider clients, and memory;
- trader/research HTTP APIs and frontend TypeScript models;
- SQL tables, migrations, repositories, and read projections;
- execution worker, broker, order intent, trade, fill, and live pathways.

Future adapters must be explicit, loss-aware, validate the result, retain the original boundary identity, and never invent a resolved issuer/instrument when the Phase 00 resolver returns unresolved/ambiguous.

## Rejected architectural alternatives

1. Add the types to `libs/contracts/domain`: rejected because that package is a legacy service/execution compatibility surface and would create ambiguous ownership.
2. Add a new top-level/internal domain subsystem: rejected because `libs/contracts` already provides the shared two-runtime dependency boundary.
3. Promote database rows, World Monitor payloads, API DTOs, TypeScript models, AI responses, broker types, Fincept structures, or benchmark records: rejected because each embeds boundary-specific semantics.
4. Merge Event with Evidence or Evidence with Observation: rejected because occurrence, source material, and measured state have different identity/time/validation rules.
5. Force UUID for all IDs: rejected because accepted Jax identities include deterministic keys, prefixed text, hashes, provider IDs, and UUIDs with different roles.
6. Use `map[string]any` or raw JSON for QuantResult extensibility: rejected in favor of named numeric values, units, times, ranks, and dimensions.
7. Introduce Protobuf, Avro, JSON Schema generation, an event bus, or a new runtime: rejected because no current consumer demonstrates that operational requirement. Go's standard JSON package is sufficient for the V1 boundary.
8. Add persistence/migrations or rewrite runtime consumers now: rejected because WP-01.02 establishes a destination contract, while deliberate migration belongs to later reviewed packages.
9. Implement content-addressed evidence, a lineage graph, event sourcing, or replay machinery: rejected as unauthorized WP-01.03/WP-01.04 scope.

## Fincept and commodity-library assessment

The Phase 01 reference notes were used only at concept level: bounded contexts, typed repository boundaries, explicit failure, and reconstructability through identifiable inputs/outputs. Fincept/Alpha Arena concepts are target comparison material, not current Jax capability. No source, schema, class topology, dependency, or runtime was copied or imported.

No mature external schema framework is needed for this package. The requirement is a small stable Go vocabulary with explicit validation and JSON, which the standard library provides. Adding a serialization dependency now would create version negotiation and operational surface without a demonstrated consumer.

## WP-01.03 deferred provenance work

The following are required follow-up, not implemented here:

- immutable EvidenceRef and content identity/hash semantics;
- complete source/provider/component version identities;
- input fingerprints and output lineage across ResearchRun, QuantResult, and Recommendation;
- artifact/dataset/policy/model/prompt/tool/build identity rules;
- immutable evidence storage/reference compatibility;
- repository-wide provenance adapters or hashing.

Evidence, Observation, ResearchRun, QuantResult, and Recommendation most directly require that enrichment. Contract versions, SourceReference, ComponentRef, and ContractRef are intentionally small extension points rather than a substitute.

## WP-01.04 deferred replay/audit work

WP-01.02 does not define an audit event, append-only stream, replay engine, current projection policy, or persistence compatibility migration. WP-01.04 must decide which aggregates use append-only records versus versioned rows/current projections and how old V1/new versions participate in deterministic replay.

The V1 contracts are replay-capable inputs because values are typed, versioned, explicitly timed, and free of maps, but that does not by itself prove reconstructability.

- Recommendation has no execution permission or order/approval fields and validation rejects any execution authority other than `NONE`.

- No approval, paper ticket, execution instruction, order intent, broker order, trade, or fill is created or mutated.
- No runtime or safety configuration is changed. Paper-only mode, live disabled, execution disabled, execution worker disabled, broker execution disabled, and maximum leverage 1x remain requirements.
- No database migration, table, repository, persisted record, or configuration change is introduced.
