# JAX HANDOVER — WP-03.02 SEC/EDGAR/XBRL EVIDENCE

Status: IMPLEMENTED

## SEC provider

The bounded provider is `pvd_sec_edgar` in `libs/sec` and uses the existing
provider capability vocabulary:

- `corporate.filing` for submissions/company filing metadata;
- `fundamentals.observation` for Company Facts observations.

The selected official read endpoints are:

- `GET https://data.sec.gov/submissions/CIK##########.json`;
- `GET https://data.sec.gov/api/xbrl/companyfacts/CIK##########.json`.

The adapter does not use a commercial SEC vendor, scrape filing HTML, use a
ticker as identity, or call EDGAR submission/account APIs. The submissions
response's `filings.files` entries are retained as an explicit
`ADDITIONAL_FILES_AVAILABLE` completeness state. An opt-in historical follow-up
is bounded by a caller-supplied maximum; an unbounded follow-up is rejected.
SEC bulk archives and arbitrary filing documents remain out of scope.

SEC's official access guidance says automated clients should declare a User-Agent
with contact information, keep request volume efficient, and observe the
published fair-access limit. The adapter sends only the configured
`User-Agent` and `Accept: application/json` headers. `LoadConfigFromEnv` requires
operator-supplied `SEC_USER_AGENT` and `SEC_CONTACT`; it has no fabricated
production contact value. Tests use a clearly non-production fixture identity.
Transport retries, rate limiting, Retry-After handling, and health state are
owned by the Phase 02 `OperationalExecutor`; no second retry framework was
added.

## Raw evidence and normalization path

Successful HTTP responses are bounded, captured as the exact response body
bytes, and passed to `provider.PersistRawPayload` before any SEC JSON parsing.
Persistence verifies the SHA-256 digest, byte count, and exact retrieval. The
normalization path then calls `NormalizeBatchStored`, which retrieves and
re-verifies the same `RawPayloadRef` before deterministic parsing/mapping.
Production composition is compatible with the already-composed PostgreSQL
`internal/rawpayloadstore.PostgresRawPayloadStore`; deterministic tests inject
the shared `MemoryRawPayloadStore` abstraction. No SEC-specific raw table or
store was introduced. Request headers, credentials, and contact configuration
are not fields of `RawPayloadRef` and are not persisted.

## Submissions semantics

The adapter retains CIK, SEC company name, accession number, form, filing date,
optional report date, primary document and description, XBRL flags, and amended
form identity. Each filing produces canonical `Evidence` V2 with a stable
issuer link, source accession identity, filing URI, publication/filing date,
collection time, and immutable raw evidence reference. Accession numbers are
validated but remain SEC source identities; they are not Jax evidence IDs.
`10-K/A` and other amended forms retain distinct evidence identities. Raw
acquisition IDs are append-only and no newest-record replacement is performed.

## CIK and canonical identity

`CIKIdentity` requires an existing canonical issuer reference and a ten-digit,
non-zero CIK. The supplied issuer mapping must contain a matching `sec.cik`
external identity. The normalizer independently resolves the CIK through an
injected `SECIdentityResolver`. No ticker-only path or Phase 00 issuer
recognition change was introduced.

## Company Facts / XBRL semantics

Facts are normalized to canonical Observation V2 records with issuer subject,
fundamental observation type, typed numeric value, original unit, source
accession, source URI, filing publication time, and raw evidence provenance.
The accompanying provider-neutral `CompanyFactObservation` research wrapper
retains:

- taxonomy and exact concept name;
- unit and original numeric lexical value;
- instant versus duration period, start where supplied, and end;
- form, accession, filed date, fiscal year/period, and frame;
- amended-form state and source payload reference.

No unlike concepts are mapped to a universal revenue/assets/income schema, no
unit conversion is attempted, and no latest/authoritative fact selection is
performed. Duplicate-looking facts remain separate when their source context
differs. Taxonomies beyond the representative US-GAAP/DEI fixtures are retained
as source semantics rather than rejected merely for being unfamiliar.

The existing generic Observation contract does not itself have typed XBRL
context fields. The bounded wrapper prevents that information loss without
changing the canonical contract or adding persistence. If future research
requires persisted/queryable XBRL semantics as first-class canonical records,
technical-lead review is required for a versioned financial-observation contract
decision; this package does not silently force that redesign.

## Dates, freshness, qualification

Filing date, report date, period start/end, instant/duration kind, frame, and
acquisition/receipt time are separate fields. Historical periods are not made
economically current by download time. The SEC capabilities declare on-demand
delivery/freshness semantics; callers must apply the accepted Phase 02
freshness evaluator where freshness is meaningful. Immutable historical filing
and fact evidence does not receive an invented TTL from this adapter.

SEC is an official regulator source, but the provider is not hard-coded as
universally qualified. Qualification remains scoped by capability, logical
source, authority, identity certainty, provenance, rights/retention, and other
existing registry dimensions. No generic trust score was added.

## Verification

Added deterministic fixture tests in `libs/sec/sec_test.go` covering provider
definition, CIK-to-issuer binding, exact bytes and digest, raw-reference header
separation, amended filings, multiple submissions, malformed/incomplete
responses, wrong media type, persistence failure, multiple XBRL concepts/units,
annual and quarterly duration facts, instant facts, filing references, frames,
amendments, deterministic normalization, and bounded additional-file state.

Commands passed during implementation:

```text
go test ./libs/contracts/provider/...
go test ./libs/sec/...
go vet ./libs/sec/...
gofmt
git diff --check
```

Live SEC verification was not attempted. The repository has no approved
production SEC contact identity, so no network request or raw live response was
captured. Deterministic fixtures are sufficient for this implementation's
request-policy and evidence-pipeline proof.

No database migration was created. No bulk/archive or large-object ingestion
was added. Trading, execution, approvals, tickets, orders, fills, paper/live
configuration, and model inference were not touched.
