## Architecture

The implementation is `libs/evidencequality`. It consumes the accepted
provider-neutral `macroevidence.MacroSeries` / `MacroObservation` contracts
through `FromMacroObservation`; no FRED, Cboe, Treasury, SEC, or market-data
DTO crosses the boundary. The generic `ObservationInput` preserves the source
series identity, explicit measurement semantics, date-only observation date,
information state, missingness, raw-payload reference, acquisition time, and
canonical provenance.

The contracts are:

- `jax.evidencequality/mapping/v1`
- `jax.evidencequality/comparison_policy/v1`
- `jax.evidencequality/cross_source_check/v1`
- `jax.evidencequality/range_check/v1`

The registry is small, code-controlled, exact-match, and versioned. It rejects
duplicate IDs and ambiguous duplicate selector pairs. Titles are not used for
matching. There is one approved mapping in this package: Cboe VIX daily close
to FRED `VIXCLS`.

The existing `internal/modules/evidencequality` package was inspected and was
not reused: it is a historical event/outcome evaluation module with market
window calculations, decision-group comparisons, and score-like report fields.
Those semantics are outside this package and would conflict with the bounded
provider-neutral evidence contract.

## Semantic compatibility and comparison policy

Before numeric comparison, the checker requires an approved mapping and exact
agreement with its provider, logical source, and provider-series selectors. It
then checks measurement type, explicitly mapped units, frequency code,
observation semantics, adjustment method, observation date, information state,
and realtime period where required by policy. A failure returns
`NOT_COMPARABLE` with a machine-readable reason code. It never selects a
winning source.

The VIX policy is `EXACT_DECIMAL` with tolerance `0`. Decimal lexical values
are parsed with `math/big.Rat` after a finite-decimal grammar check. Thus
`14.50` and `14.5` agree while both lexical values remain in the result.
`NaN`, `Inf`, exponent/fraction syntax, and malformed values fail closed.
No float epsilon is used. Missing values retain their source marker and are
never converted to zero.

## Cboe VIX ↔ FRED VIXCLS

The mapping is `eqm_cboe_vix_fred_vixcls`, version `v1`. It binds:

- Cboe provider `pvd_cboe`, logical source
  `src_cboe_vix_daily_history`, series `VIX`;
- FRED provider `pvd_fred`, logical source `src_fred_economic_data`, series
  `VIXCLS`;
- measurement `VIX_DAILY_CLOSE`, daily frequency `D`, and explicit
  `CLOSE_VALUE_BY_OBSERVATION_DATE` semantics.

FRED's `VIXCLS` documentation identifies the Chicago Board Options Exchange
as the source, describes the series as daily close index data, and carries
copyright/reprint language. The mapping therefore classifies the relationship
as `SAME_ORIGIN_REDISTRIBUTED`, not `INDEPENDENT`. The explicit unit bridge is
from Cboe's `index points` label to FRED's `Index` label under this approved
mapping; it is not inferred from title similarity.

This checks distribution/normalisation consistency. An agreement produces an
independent-source count of `1`, not `2`. The result retains both source
observation references, both raw acquisition references, and both evidence
lineages. Raw Cboe/FRED bytes are not copied into the result or documentation.

Authoritative source references:

- [Cboe VIX historical source URL](https://cdn.cboe.com/api/global/us_indices/daily_prices/VIX_History.csv)
- [FRED VIXCLS series notes](https://fred.stlouisfed.org/series/VIXCLS)

## Treasury ↔ FRED negative control

The source descriptions were reviewed before coding. Treasury's Daily Treasury
Par Yield Curve documentation describes `BC_10YEAR` as a par yield read from a
daily interpolated curve based on indicative bid-side quotations near 3:30 PM,
and notes that a ten-year par yield can exist without a security with exactly
ten years remaining. FRED `DGS10` is documented as Board of Governors / H.15
`Market Yield ... 10-Year Constant Maturity, Quoted on an Investment Basis`.

No Treasury↔FRED equality mapping is approved. The registry cannot compare
these series merely because both mention a ten-year Treasury yield. The
regression changes the provider-series identities to Treasury
`daily_treasury_par_yield_curve:BC_10YEAR` and FRED `DGS10` and gets
`NOT_COMPARABLE / MAPPING_NOT_APPROVED`.

Authoritative source references:

- [Treasury Daily Treasury Rates and par-yield methodology](https://home.treasury.gov/resource-center/data-chart-center/interest-rates/TextView?page=0&type=daily_treasury_yield_curve)
- [FRED DGS10 series notes](https://fred.stlouisfed.org/series/DGS10)

## Outcomes and reason codes

The checker supports `AGREE`, `DIVERGE`, `LEFT_MISSING`, `RIGHT_MISSING`,
`BOTH_MISSING`, `NOT_COMPARABLE`, and `INDETERMINATE`. A divergence retains
both lexical values and exact absolute difference; it does not select a
winner. Compatibility failures identify the failed dimension with deterministic
codes such as `UNIT_MISMATCH`, `FREQUENCY_MISMATCH`,
`INFORMATION_STATE_MISMATCH`, `OBSERVATION_DATE_MISMATCH`, or
`MAPPING_NOT_APPROVED`.

## Temporal and information-state safety

Observation dates remain separate from publication/availability times and
`AcquiredAt`. The checker never manufactures a timestamp from a date, market
close, feed metadata, or acquisition time. `CURRENT`, `AS_OF_REALTIME_DATE`,
`VINTAGE_DATE`, and `INITIAL_RELEASE` remain explicit; a current observation
does not silently replace a historical/as-of observation. Realtime periods are
compared only when the mapping policy requires alignment. A matching date is
not treated as proof of matching public availability or historical knowability.

## Lineage and independence

The result's canonical `Provenance` combines the immutable lineage inputs from
both observations, deduplicating identical immutable references, and keeps
each side's evidence references plus raw-payload acquisition references. The
effective lineage is downgraded to `SAME_ORIGIN_REDISTRIBUTED` when logical
source identity or provider-series identity shows the same origin. Identical
raw content across otherwise different selectors is `UNKNOWN`, never
independent. Therefore an original publisher plus a redistributor, or two
acquisitions of the same source data, cannot create an independent count of 2.
Unknown qualification remains unknown; this package does not create a
qualification GO state or a numeric trust score.

## Range and completeness

`CheckRange` is bounded to exact observation-date keys. It reports overlap
start/end, candidate dates, compared rows, agreements, divergences, left-only
dates, right-only dates, both-missing count, diagnostics, and completeness.
It performs no aggregation, resampling, correlation, RMSE, or signal analysis.
The summary is `COMPLETE` only when both input artifacts are explicitly marked
complete; unknown or incomplete artifact/paging state yields `INCOMPLETE`.
Date-set differences remain visible and are never hidden by a one-date
agreement.

## Live verification and limitations

The existing approved Cboe live smoke path was attempted with
`JAX_RUN_LIVE_WP0305=1` and passed against the official CSV endpoint. A live
cross-source pass requires both that path and the approved FRED provider with
an already configured `FRED_API_KEY`. No key was configured, requested,
embedded, logged, or bypassed. Live Cboe↔FRED verification is therefore
blocked for the FRED side; deterministic provider-neutral fixtures remain the
cross-source verification evidence and are not presented as a live pass.

This package does not implement source ranking, trust scoring, qualification
decisions, release-time inference, database persistence, signals,
recommendations, execution, or Phase 04 event intelligence. The exact VIX
mapping is intentionally narrow; additional mappings require authoritative
documentation and code review.
