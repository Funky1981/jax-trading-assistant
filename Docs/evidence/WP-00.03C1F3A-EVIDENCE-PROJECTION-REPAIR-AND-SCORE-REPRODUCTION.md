## Proven root cause

Live C1F3 execution is explicitly routed by `ExecuteDiagnostic` to `analyseC1FEvent`, which calls `ParseValidateAndApplyC1F`. The accepted `EventResult` therefore contains the C1F-parsed raw model output, typed attribution policy decision, effective mapping, and deterministic resolution.

The historical audit builder did not use that accepted result. It selected a parser only from `attempt.SchemaVersion`. Because C1F deliberately reuses the v5 output contract, it sent every accepted C1F attempt to `ParseValidateAndApplyV5`, ignored that function's validation errors, and persisted the returned pointers. The historical v5 parser returns all projection pointers as `nil` when validation fails.

Exactly 33 accepted C1F attempts exercised the one intentional C1F/v5 validator difference: C1F permits a structurally valid `UNRESOLVED` result with HIGH, MEDIUM, or LOW confidence, while historical v5 requires LOW. The independent recovery found this exact historical-route error for all 18 defective Generalization records and all 15 defective Boundary records:

`UNRESOLVED mapping requires LOW mapping_confidence`

Historical C1E/v5 execution is unaffected because both its live execution and audit projection use `ParseValidateAndApplyV5`. Historical v4 likewise remains on its original v4 parser/guard route.

## Future projection repair

The audit path now carries the projection produced by the live accepted route rather than reparsing accepted output through a schema-only guess. Routing is explicit for historical v4, historical C1E/v5, and frozen C1F. Accepted projections must match the frozen profile route and contain every required layer; mismatched, incomplete, and unknown profile/version combinations fail closed. Rejected attempts cannot carry an accepted projection.

For accepted C1F output the persisted attempt now retains:

- parsed raw model output;
- typed attribution;
- unchanged C1E policy result;
- effective semantic mapping;
- unchanged deterministic resolution.
